# Glossary

[⬅ Back to README](../README.md)

| Term | Definition |
|---|---|
| **Agentic AI** | An AI system that can plan across multiple steps, call tools, and take actions, not just generate text. |
| **Attack surface** | Every point where an attacker can interact with or influence a system. |
| **Cross-tenant leakage** | One tenant/customer receiving another tenant's data due to broken isolation. |
| **Denial of wallet** | Forcing excessive paid API/compute usage to run up cost rather than crash a service. |
| **Direct prompt injection** | An attacker's own input overrides intended system instructions. |
| **Excessive agency** | An agent holds more capability/autonomy than its task requires. |
| **Human-in-the-loop (HITL)** | A required human approval step before a high-risk action executes. |
| **Indirect prompt injection** | Malicious instructions embedded in external content (documents, web pages, tool output) that the model treats as trusted. |
| **Jailbreak** | A technique to bypass a model's safety training/instructions. |
| **Least privilege** | Granting only the minimum permissions required for a specific task. |
| **MCP (Model Context Protocol)** | An open protocol connecting AI applications/agents to external tools and data sources. |
| **Membership inference** | Determining whether a specific record was part of a model's training data. |
| **Model extraction** | Reconstructing a functional copy of a model through repeated queries. |
| **Model inversion** | Reconstructing training data (or approximations of it) from model outputs. |
| **RAG (Retrieval-Augmented Generation)** | Retrieving external documents/data to ground an LLM's response in context. |
| **Tool poisoning** | Malicious or manipulated tool descriptions/metadata/responses that influence agent behavior. |
| **Trust boundary** | A point where data or control crosses between components with different levels of trust. |
| **Vector database** | A database storing embeddings (numeric representations of content) for similarity search. |
